HOT Info Orbs

Five round displays on your desk showing the time, the weather and the markets. They update over WiFi and are set up from any browser. It's built as a club kit, so it's hard to get wrong and cheap to get into.

A derivative of Brett Turner's Info Orbs. The firmware started as his; the carrier board, power design and everything under “What we added” are the club's.

Software changes

The baseline is upstream's main branch as of February 2025, the point this project forked from. Gray text under an item says how the original did it.

Settings from a browser

  • A settings page at http://<orb>/settings. It covers rotation time, tickers, weather town, units and light/dark mode, time zone, 12/24 hour and AM/PM, starting clock face, clock and shadow colors, dim and screens-off hours, which pages to show, and upside-down mounting.Was: edit config.h, rebuild, reflash over USB.
  • Settings are stored on the orb and survive restarts and firmware updates. config.h supplies the defaults, and one button resets to them.
  • The page is grouped into Setup, Display and Advanced, with a contents list at the top and a bar that stays on screen with the group links and a Save button. The group you are in is marked with a glyph and an underline, not by color alone.Was: one long page, Save at the bottom.
  • The orb checks every field before it saves. Problems show next to the field, marked ✔ / ✖ / ⚠ as well as by color.
  • Upload your own start-up picture. Your browser crops and shrinks it to 240 × 240, and a bad file falls back to the built-in logo.Was: fixed when the firmware was built.

Night and what's on screen

  • Two separate schedules: dim hours and screens-off hours. Use either, or both, so the orbs can dim in the evening and go dark at bedtime. Where they overlap, off wins.Was: dim hours only.
  • Start and end times are typed, to the minute: 22:30, 7:30, 10pm or 10:30 pm all work. An orb updated from the hour-only firmware keeps its hours.Was: whole hours from a drop-down.
  • Screens off sends the display chip's own off and sleep commands to all five panels. Any button wakes them for a minute. The backlight stays on, so the screens go blank but still glow; they are not black. Truly black needs a power switch on the displays' 5 V feed; what that takes is in REQUIREMENTS.md.
  • Choose which pages appear. Tick one to keep it on screen, or several to rotate through them; the buttons move between ticked pages only.Was: every page, always.

Updates over WiFi

  • Upload new firmware from a browser at /update, or straight from PlatformIO.Was: USB cable, every time.
  • Two firmware slots. A new image counts as good only once it reaches WiFi; otherwise the orb rolls back to the previous one.
  • The update and settings pages show the running version, commit and build time.
  • The boot screen shows how much of the firmware slot is used, so the headroom is visible without a laptop.
  • When WiFi fails, orb 5 says which case it is: never set up, network not found, or wrong password. A wrong password is reported in about 18 seconds and not retried; a missing network is looked for again while the setup portal runs. Joining from the portal restarts the orbs.Was: one generic screen, and about 5 minutes to give up on a wrong password.

Keys and security

  • API keys live in your own secrets.h, which git ignores.Was: keys compiled into config.h, and the template shipped with live keys.
  • The build stops if a key is missing or empty. You get a compile error at your desk instead of a blank orb on the bench.
  • An optional password protects both the settings and update pages. Without one, anyone on your network can use them, and both pages show a ⚠ warning. The page never shows a stored key.

Weather

  • Towns with spaces in their names work; the location is now URL-encoded.Was: spaces could break the request (upstream issue #337).
  • Personal Tempest weather stations, up to two, each with its own page and a label of up to 16 characters.
  • The Tempest page shows live readings: conditions, feels-like, humidity, and wind as a range from average to gust.
  • The 96 KB Tempest reply is streamed through a filter that keeps 744 bytes. The settings page shows ✔ / ✖ for each station's last fetch.
  • Sunrise and sunset times above the weather icon, and a small drawing of tonight's moon below it. Times come from the weather source; the moon phase is worked out on the orb, because Tempest does not supply one.
  • In 12-hour mode the clock on the weather page shows 9:05, centered, not 09:05.Was: a leading zero, and the time sat right of center.
  • The Tempest token is pasted on the settings page, so the ready-made release file works with a station too. Every build carries the Tempest code (about 20 KB); without a token it stays idle.

Custom pages

  • Up to two MQTT pages of five orbs each, set up on the settings page: a broker, then one topic, label and unit per orb. Works with Home Assistant or any other MQTT source.Was: one page, laid out by a JSON message with pixel positions.
  • A JSON page that reads any web address, set up the same way.
  • Long values wrap onto up to three lines, and a line break in the message starts a new line, so 5pm can sit above the act's name. The orb measures the text to find the largest size that fits, instead of estimating it.Was: one line, sized by an estimate. Long text came out as small as 10 px and could still run off the screen.
  • One text size for the whole page by default, so five orbs side by side match. A per-page setting lets each orb be as large as fits instead.Was: each orb sized on its own, from 10 px to 40 px across one page.
  • Ready-made Home Assistant recipes in CUSTOM-PAGES.md, including tonight's act at each of The Villages' five town squares.

Waking eyes

  • At start-up the orbs wake up: eyes on orbs 2 and 4 open while WiFi connects, then look around while the data loads. Orb 3 shows the HOT hand as a nose and orb 5 the start-up progress. A “Waking eyes” setting turns it off; it is on by default.
  • If WiFi fails after the waking eyes, the orbs go cross-eyed: eyes on orbs 1 and 3, the nose on orb 2, the message on orbs 4 and 5.
  • Eye lids in eleven styles, picked on the settings page: Taupe (default), Skin, Tan, Robot, Stone, Ash, Black, and the metal finishes Chrome and Stainless, plus Frost and Night King (dark sockets). A lid demo cycles through every style so you can choose.
  • Iris color: Natural (default), Blue, Brown, Green, Grey, Amber, Violet, Red or Ice. Night King is a whole eye rather than a color: a seven-pointed star for a pupil, dark specks in the iris and a glowing blue eyeball; pair it with the Night King lids and eyelashes off. Eyelashes switch on or off. Both apply to the demo too.

Port and branding

  • Ported to the Seeed XIAO ESP32-S3 / XIAO ESP32-S3 Plus pin map; it runs on an assembled rev 2.5 carrier board. Every pin is a setting in config.h, so a different module needs a new pin map, not new code.
  • The splash reads “HOT Info Orbs by HOT-Team”. The Hands-On Tech logo is in the repo, ready to become the built-in picture.Was: “Info Orbs by brett.tech” and Brett's logo.

Quality

  • Unit tests run on a laptop and in CI for settings validation, weather parsing, the sun and moon, and custom pages: 108 tests, including WiFi roaming and MQTT text fitting.Was: none.
  • The linter reports problems and no longer commits changes back, so the repository only moves when a person moves it.
  • An upstream bug is fixed: an uninitialized loop counter in the page rotation.
  • A written setup guide goes from an empty laptop to a running orb, and a traps file records every mistake that cost time once.Was: Brett's assembly video and README.

Hardware changes

A new carrier board

  • Carrier board by Yang and Scott, KiCad 10: the v1.1 board reworked for the XIAO. The libraries live inside the project, so you clone it and open it; there's nothing to install.Was: upstream's 2-layer board for an ESP32 dev kit.
  • The XIAO ESP32-S3 or S3 Plus goes on 2.54 mm headers (swappable) or solders flat on its castellations. Both share the edge pins, so either fits.Was: a 30/38-pin ESP32 dev kit.
  • Fixed in review before fab: the fifth display's DC line connected, a button moved off a strapping pin, and a ground pour added.

Power that stays cool

  • Each display gets 5 V and regulates its own supply, so the module's regulator carries only the ESP32.Was: all five displays on the module's 3.3 V regulator. Builders reported 82 °C.
  • Measured on a Nordic PPK II: 342 mA (1.71 W) typical and a 1.15 A surge at power-on. That's why the spec calls for a 2 A supply.

Built to be reproducible

  • JLCPCB's design rules are loaded into the design-rule check.Before: the check was running against default rules.
  • The exact gerbers sent to the fab are archived and never regenerated. Ten v1.1 boards were ordered on 29 Aug 2026, and 30 of the XIAO board (rev 2.5) on 25 Oct 2026.
  • A 3D assembly model (STEP) is available for enclosure design.
Two builds, one carrier board

Basic and Advanced

Basic is the Seeed XIAO ESP32-S3; Advanced is the XIAO ESP32-S3 Plus. Same carrier board, same edge pins, same firmware binary — the Plus only adds flash the build does not yet use. The builder picks either. The firmware runs on an assembled rev 2.5 carrier board with a XIAO; the boards were ordered 25 Oct 2026.

What it shows

Pages in the rotation

The orbs rotate through their pages on a timer set from the settings page. Pressing a button restarts the countdown.

Clock

Seven-segment, Nixie, or your own JPG digits. 12 or 24 hour, with custom colors and shadow.

Weather

Current conditions, today's high and low, a 3-day forecast, and sunrise, sunset and the moon. From Visual Crossing, or your own Tempest station.

Stocks

Five tickers, one per orb: stocks, forex or crypto, from Twelve Data.

Custom pages

Your own page in the rotation, set up on the settings page: a JSON file from any web address, or one live value per orb from MQTT (Home Assistant), on up to two pages of five. Long values wrap to fit. No rebuild.

And more

A Parqet portfolio from upstream, switched on in config.h.
